## Your note (2026-11-24)
After the first real load with the files (D10, it loaded complete), you asked to report the server files that are not
attachments separately, and what may have happened to the files no attachment points to.

## What was wrong
*Server files no attachment points to* mixed two different things:
- files that were never attachments: `dummy` placeholders, the database backups in `arxeio/backups/`, the old
  `protocol.sqlite`, and the index a file-copy tool leaves in a hidden `.hist/` folder;
- real attachment files without a row, with no hint why.

## What the old app does with files (checked in its code)
- A protocol's attachment goes to `arxeio/<folder as typed>/`; without a folder, to `arxeio/` itself, or
  `arxeio/emails/` for an e-mail. So those two places can hold real attachments.
- Changing a protocol's folder moves its files and updates the rows. Deleting an attachment moves its file to `trash/`
  (the import finds it there). Deleting a protocol deletes its files and rows.

So the old app does not leave files behind by itself. A file without a row usually means the export and the file copy
were not taken at the same moment, or the same folder is written two ways on the server (`Φ43/` and `Φ.43/`, D08).

## What changed
- `ServerFiles::notAttachment`: unmatched files outside `arxeio/` and `trash/`, in hidden folders or with hidden
  names, `dummy`, `Thumbs.db`, `desktop.ini`, `arxeio/backups/…` and `arxeio/protocol.sqlite*` are counted on their own
  line, *Other server files, not attachments*, and listed under *Not attachments* with `--list`. A file a row points
  to is always copied, wherever it is.
- `ServerFiles::explain`: with `--list`, every other file without a row has a reason next to it:
  - *a row has this name at …*: the same file in another folder;
  - *protocol N/YYYY is not in the database (saved after the export?)*: the stored names start with
    `<number>-<YYYYMMDD>_`; this kind is also counted in the summary;
  - *protocol N/YYYY (folder …) has no attachment with this name*: replaced or renumbered on the server;
  - *no protocol number in the name*.
- Still counts only without `--list`; names (private) only with it.
