## Your note (2026-11-24)
A fresh copy of the real data should be the phpMyAdmin export **together with** the server's attachment files, and
loading it should go through the move to the new version. You asked for this to be part of *Real data: load* rather
than a separate script, with the files copied **by the database**. Server files that no attachment points to are
listed, not copied.

## What was wrong
- The copy worked **directly on** `local-data/storage/app`, the files you copied from the server. Every test changed
  them: uploads, the trash, and the Φ.43 → Φ.46 merge. After a merge, a freshly loaded export said *Φ.43* again
  while its files were already under Φ.46, so the database and the files disagreed.
- *Load* only counted the files it found. The folder glossary and the merge were a separate manual step (try-it 38).

## What changed
- **`local-data/server-files/`** (new) holds the server's `storage/app` as it is: `arxeio/`, `trash/` and the rest.
  Nothing ever writes there. You can top it up with only the new files.
- **`php artisan attachments:import <folder> [--apply] [--list]`** (`App\Services\Attachments\ServerFiles`):
  - every attachment row, including those in the trash, gets its file from the server folder at the path the row says;
  - rows trashed before R4b find their file in `trash/`, the same rule as the app uses (`Attachment::fileCandidates`);
  - the case of the letters does not matter, as on the Windows server: a row saying `arxeio/φ.12/…` finds
    `arxeio/Φ.12/…`. The file is copied to the row's path, so the app finds it on Linux;
  - a file already there with the same content is skipped. A different one is reported and never overwritten;
  - server files no row points to are only counted (names with `--list`);
  - without `--apply` it only counts. It prints counts only; names are printed only with `--list`.
- **`./dev.sh real load`**: dump → migrate → empty the copy's `storage/app/arxeio` and `trash` → `attachments:import
  local-data/server-files --apply` → measure the files (D03) → `folders:glossary --apply --brief` (glossary, aliases and
  Φ.43 → Φ.46) → summary.
  - A `server-files/` folder without `arxeio/` stops the load before anything is deleted.
  - Without a `server-files/` folder, the files already in `local-data/storage/app` are used as before.
- `folders:glossary --brief`: counts only, no folder codes, so the load output stays short.
- VS Code task renamed to **Real data: load newest backup + files (local-data/db, local-data/server-files)**.
- [docs/LOCAL-REAL-DATA.md](../LOCAL-REAL-DATA.md): the new folder and what load does. OWNER-TODO: try-it 61, and the
  import step added to the deployment steps.
