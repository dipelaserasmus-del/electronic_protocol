# S04 — Real configuration file (`.env`) was committed

| | |
|---|---|
| Status | ✅ Fixed in the repository · ⚠️ **owner action needed on the production server** (below) |
| Branch | `task/S04-env` |

## What was wrong
`.env` — the file that holds the application key and passwords — was committed to the repository
(inherited from the original project) and so is public. `.env-docker` also carried a fixed `APP_KEY`.
The passwords in both are placeholders (`p@ssw@rd…`, `gm@ilp@ss…`), but the **application keys are real
values, public for years**. Any installation that copied one of these files and kept its key uses a key
everyone can read: it signs session and "remember me" cookies, so an attacker could forge them.

## Fix
- `.env` removed from git (`git rm --cached`; nobody's local copy is deleted by this commit) and ignored
  (also `.env-old`, `.env.backup`).
- `.env-docker`: `APP_KEY` emptied — `docker-install.sh` already generates a fresh key.
- `.env.example` rewritten as the single, current template (MySQL, Docker host names, mail timeout, IMAP).
- CI data-hygiene check now also fails if `.env` is ever tracked again.
- Checked: the app stores **no encrypted data** (no `Crypt::`, `encrypt()`, `encrypted` casts; sessions not
  encrypted), so changing the key only logs users out — nothing is lost.

## ⚠️ Owner action on the production server
Only if the server's code is a **git clone** that you update with `git pull`:

1. **Before the next `git pull`**, back up the configuration:
   ```bash
   cp .env ~/env.backup-$(date +%F)
   ```
   (git may delete a tracked file that this commit untracks.) After pulling, if `.env` is missing:
   ```bash
   cp ~/env.backup-YYYY-MM-DD .env
   ```
2. **Check whether the server uses one of the public keys.** In the server's folder, compare the first
   characters of its key with the keys that were in the repository:
   ```bash
   grep '^APP_KEY=' .env | cut -c1-20
   ```
   If it starts with the same characters as `git show 92eb910:.env | grep APP_KEY | cut -c1-20` or
   `git show 92eb910:.env-docker | grep APP_KEY | cut -c1-20`, generate a new one:
   ```bash
   php artisan key:generate --force
   ```
   (Docker: `docker compose exec app php artisan key:generate --force`, then `docker compose exec app php artisan config:cache`.)
   Effect: everyone is logged out once. No data is affected.
3. The mail/IMAP passwords in your real `.env` were never in the repository — nothing to change there.
