# F07: `./dev.sh real load` fails with "Table 'users' already exists"

| | |
|---|---|
| Status | ✅ Fixed (local real-data copy; also affects updating the production server, see owner actions) |
| Branch | `task/F07-real-load-legacy-baseline` |
| Found by | the owner, loading the production backup on Fedora (L01, 2026-11-16) |

## What was wrong
The import of the backup succeeded. The next step, `php artisan migrate`, then failed:
```
Creating migration table ... DONE
2014_10_12_000000_create_users_table ... FAIL
SQLSTATE[42S01]: Base table or view already exists: 1050 Table 'users' already exists
```
"Creating migration table" shows that the backup has **no `migrations` table**: the production installation was
not set up with `artisan migrate`. Laravel therefore thinks no migration has run and tries to create every table
again. No data was read for this diagnosis; the error message is enough.

The same thing would happen on the production server itself on the first `php artisan migrate` (needed after
deploying Batch 1).

## Fix
New command `php artisan migrate:adopt-legacy` (`app/Console/Commands/AdoptLegacySchema.php`):
- if the database already has migration records, or has no `users` table (empty database), it does nothing;
- otherwise it creates the `migrations` table and records each `create_<table>_table` migration **whose table
  exists** as already applied. A table that is missing is created later by `migrate`.

Changes to existing tables (e.g. S00's `2026_11_12_000001_users_role_default_reader`) are not recorded, so `migrate`
still applies them. `./dev.sh real load` now runs `migrate:adopt-legacy` before `migrate --force`.

## How verified
- `tests/Feature/AdoptLegacySchemaTest.php` (3 tests): a database shaped like the backup (all tables, no
  `migrations` table, old `role_id` default 1) is adopted, `migrate` then succeeds, applies the S00 change and keeps
  the rows; a missing table is not recorded and gets created; a database with migration records is left alone.
- `tests/shell/dev-sh.test.sh`: `real load` calls `migrate:adopt-legacy`.
- Full suite: 117 PHPUnit tests green. Not visible in the browser, so no e2e spec.
- The owner re-runs `./dev.sh real load` on the real backup (Claude never sees it).
