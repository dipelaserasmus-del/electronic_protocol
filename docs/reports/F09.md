# F09: Docker build: apt retries and time-outs; CI job time limits

| | |
|---|---|
| Status | ✅ Done |

## What was wrong (2026-11-23)
- **Symptom:** the CI jobs that build the Docker image (*Docker image builds*, both architectures, and *Browser tests*,
  which starts the stack) hung at *Build app image* for over 50 minutes, twice in a row, on PR #97. No code of ours
  was involved.
- **Cause:** Ubuntu's security update server (`security.ubuntu.com`) answered only some requests. The same was seen
  from the owner's computer: `apt-get update` in a plain `ubuntu:26.04` container was still waiting after 2½ minutes;
  one request to the server answered in 3.5 s, the next got nothing in 15 s.
- **Why it hung:** apt waits a long time on a server that stops answering and does not try again. The CI jobs had no
  time limit of their own, so GitHub's default of 6 hours applied.

## What changed
- **`Dockerfile`:** before installing packages, the image gets `/etc/apt/apt.conf.d/80-retries`:
  `Acquire::Retries "5"`, and `Acquire::http::Timeout` / `Acquire::https::Timeout` of 30 seconds. A request that gets
  no answer gives up after 30 s and is tried again, up to 5 times, instead of waiting without end. The same applies
  wherever the image is built: CI, the dev stack and, later, the production server's Docker stack.
- **`.github/workflows/ci.yml`:** every job has a `timeout-minutes`, about three times its usual length (browser tests
  usually take 14 minutes, the image builds 2–13):

  | Job | Limit |
  |---|---|
  | Tests (PHP 8.4 / 8.5) | 15 |
  | Dependency security audit | 10 |
  | Progress tracker & data hygiene | 10 |
  | Browser tests | 45 |
  | Docker image builds | 40 |
  | Docker image builds (arm64) | 30 |
  | dev.sh (Linux, macOS) | 15 |

  A job that hangs now fails within the hour with a clear time-out, and can be re-run.

## How verified
- In a plain `ubuntu:26.04` container, the Dockerfile's line writes the file, and `apt-config dump` shows
  `Acquire::Retries "5"`, `Acquire::http::Timeout "30"` and `Acquire::https::Timeout "30"`.
- A full local image build (`docker build --no-cache`) during the outage: see the PR.
- The workflow file parses as YAML. This PR's own CI run is the end-to-end check: it builds the image with the new
  settings.
