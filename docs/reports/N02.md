# N02: Laravel structure modernization

| | |
|---|---|
| Status | ✅ Done; no visible change for users |

## What changed
The app still had the Laravel 5-era skeleton, even though it already ran on Laravel 13.

| Before | After |
|---|---|
| Models in `app/` (`App\User`, `App\Protocol`, …) | `app/Models/` (`App\Models\User`, …). No database change: no table stores class names (checked: no polymorphic columns) |
| `bootstrap/app.php` binding `App\Http\Kernel`, `App\Console\Kernel`; `RouteServiceProvider`; provider list in `config/app.php` | Laravel 11+ `Application::configure()` in `bootstrap/app.php`: routes, middleware aliases (`admin`, `writer`, `email`, `limitList`, `redirectAfterLogin`), `TouchUserActivity` appended to the web group, `/up` health check; `bootstrap/providers.php`; packages by auto-discovery |
| 7 middleware classes that only restated framework defaults (TrustProxies, TrimStrings, CSRF, cookies, maintenance, Authenticate, RedirectIfAuthenticated) | framework defaults; the landing page `/home/list` is `App\Support\Home::LIST` (`redirectUsersTo`) |
| Routes as `'ProtocolController@index'` strings; login required only by each controller's constructor | `[ProtocolController::class, 'index']`; **every non-public route is inside one `Route::middleware('auth')` group**, so a new route can't be left open by forgetting the constructor |
| Controller constructors calling `$this->middleware(...)` | `HasMiddleware::middleware()` with the same rules (writer/admin/e-mail/list-limit, same `only`/`except` lists) |
| Policy in `AuthServiceProvider` | `Gate::policy()` in `AppServiceProvider` |
| Unused: `VerificationController` (no routes), `routes/api.php`, `routes/channels.php`, Broadcast/Event providers, `_ide_helper.php` (generated for Laravel 5 in 2017) | removed |

`dev.sh` (`real load` summary and the IMAP setting) uses the new model names.

### Bug found and fixed
The B04 error handler asked for the current web request while logging. **Outside a web request** (artisan
commands, scheduled jobs) that failed with "Target class [request] does not exist", so the original error was
lost. It now logs the error with a reference code and leaves out URL/method when there is no request.

## How verified
- **Safety net first** (`tests/Feature/RouteAccessTest.php`, committed before any change): a snapshot of all
  64 app routes with their full middleware list (route + controller level, `tests/Feature/snapshots/route-middleware.json`).
  The restructured app produces **the identical snapshot**. Also: every non-public route requires login; a guest is
  redirected to `/login` from every protected route; a logged-in user opening `/login` lands on `/home/list`.
- New test `test_errors_outside_a_web_request_are_logged_with_a_reference_code` (failed before the fix).
- Two auth actions were `protected` (`showLoginForm`, `showLinkRequestForm`); the old base controller allowed that,
  the new one doesn't. Found by the existing `AuthTest`, made `public`; all route actions were checked.
- Full suite 135 tests green; `dev.sh` checks green; browser suite 9/9 green (`./dev.sh e2e`: login per role,
  protocol list, search, settings, new protocol with receipt, e-mail registration, backup).
- `php artisan list` still has `migrate:adopt-legacy` (needed for the final data migration).
