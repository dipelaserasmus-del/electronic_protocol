## What was missing
The attachments table knew a file's name and path, but not its size, its content fingerprint or who moved it to the
trash. Later tasks need them: file sizes in the attachment panel and the inbox (R1c, R5c), finding identical files
(A05), the trash page with "deleted by" (R4b).

## What changed
- Migration `2026_11_16_000004_attachments_size_hash_deleted_by`: `size` (bytes), `sha256` (indexed) and
  `deleted_by` (user id). Written so it can run again on a schema that already has them (as the other changes to
  old tables).
- Every stored file is measured again on each save of its row (also when a new upload with the same name overwrites
  the file at the same path: review finding). Size and SHA-256 on save (form upload, e-mail registration, any later
  code): `Attachment` model, measured on the stored file (after the stamp, when one is added).
- Moving an attachment to the trash records the user: the trash button, and the administrator's
  *Διαγραφή ληγμένων* (that one is a single query that skips the model, so it sets `deleted_by` itself).
- `php artisan attachments:fill-metadata`: measures the existing files (only those without a size; `--all` measures
  again). It does not touch `updated_at` (not a change by a user) and prints counts only. It also finds files of
  attachments in the trash: the trash button moves the file from `arxeio/` to `trash/` but leaves the old path in the
  database (a bug for R4b to fix with the trash rebuild). `./dev.sh real load` now runs it after `migrate`.
- Not in the migration on purpose: hashing several thousand files would make the deployment wait.

## How verified
- `AttachmentMetadataTest` (8 tests): upload through the form (size and hash of the stored file); no file / missing
  file → empty, no error; replacing the file measures again; trash button and *Διαγραφή ληγμένων* record the user
  (and only the expired file goes to the trash); the command measures rows written without the model (as in a
  backup), finds a trashed file under `trash/`, counts the missing one, keeps `updated_at`, and a second run measures
  nothing.
- Review findings (Codex, both fixed and tested): a file overwritten at the same path kept the old size/hash
  (`test_file_overwritten_at_the_same_path_is_measured_again`); a trashed attachment whose old path now holds a newer
  file was measured on the newer file; `trash/` is now checked first (`test_trashed_attachment_is_measured_in_the_trash_first`).
- `StoreFromEmailTest`: the stored `.eml` and its attachment have the right size and hash.
- `AdoptLegacySchemaTest`: a production-shaped backup without the columns gets them after `migrate:adopt-legacy` +
  `migrate`.
- `tests/shell/dev-sh.test.sh`: `real load` runs the command.
- Demo data in the running app: `./dev.sh artisan attachments:fill-metadata` → *Attachments measured: 109; file not
  found: 0.* Nothing changes on screen yet (the new screens show the sizes), so there is no browser test.
- Full suite: PHPUnit 240 (this branch starts from `master`, without D02's tests).
