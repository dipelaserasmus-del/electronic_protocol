## What was asked (backlog, Phase 5)
«Append-only `audit_log` table (user, action, entity, old→new values, IP, time); automatic capture of create/update/
delete on protocols, attachments, assignments, users, folders, settings; logins / logouts / failed logins; attachment
downloads; email registrations; retention setting». Owner (plan): «required, low priority: who did what and when».

## What was there
Nothing: the application did not keep who changed a protocol, an attachment or a setting, or who signed in. Only a
few traces existed (who moved an attachment to the trash, a note when a protocol came back from the trash).

## What changed
- **Table `audit_log`**: when, who (user and user name as it was), from where (IP), the action, what it is about
  (and the protocol it belongs to), each changed field's old and new value, and what helps to read it (the protocol's
  number, a file name, a setting's key). No foreign keys, so an entry outlives its user and protocol.
- **Recorded by themselves** (model events): protocols, attachments, assignments, folders and their automatic
  assignments, users, settings (also the stamp's design): created, changed (only what changed), to the trash, back,
  deleted for good.
- **Recorded where they happen:** sign-in, sign-out, failed sign-in (the user name typed, never the password); every
  download (and whether with the stamp); a protocol to the trash, back (with its old number if it got a new one) and
  purged; an e-mail registered from the Inbox; a folder merge (one entry with what moved).
- **Never written:** passwords (only «changed», `***`), a user's own view preferences, the application's bookkeeping
  rows. The trash's daily clean-up is recorded without a user, marked automatic (it runs during some user's request,
  but is not theirs).
- **Append-only:** the application cannot change or delete an entry; old entries leave only by **`AUDIT_KEEP_DAYS`**
  in `.env` (empty = keep everything; daily, with the trash's clean-up, and `php artisan audit:purge`). In `.env`, not
  *Ρυθμίσεις*: the page is as the owner planned it (R6m), and this is decided once.
- **A failure to write the log never stops the user's work** (it is reported in laravel.log).
- Found and fixed on the way (in this PR): the trash's daily clean-ups counted 0 when wrapped for the log (an arrow
  function's copy of the counter); caught by the new test and the existing trash tests.
- Feature guide **[docs/AUDIT-LOG.md](../AUDIT-LOG.md)** (for administrators; for developers: where the code is, what
  is not recorded by itself and how to record it, the rules the code keeps); `docs/SETTINGS.md` lists
  `AUDIT_KEEP_DAYS`.

Nothing is shown yet: X02 adds *Διαχείριση → Ιστορικό* and each protocol's history.

## How it was verified
**PHPUnit** — `tests/Feature/AuditLogTest.php` (10 tests): a protocol created and changed (who, when, IP, only the
changed fields, no entry for a save without changes); an attachment to the trash, back, purged; a protocol with its
assignment to the trash, back, and the daily clean-up recorded without a user; a user's password never written, their
preferences not recorded; settings with their key, not the application's own rows; folders; sign-in, failed sign-in
(no password anywhere in the log), sign-out; a download; append-only and the retention; a broken log does not stop a
save. `EmailRegistrationTest` (the Inbox entry) and `FolderGlossaryTest` (the merge entry) extended. Full suite green.

**In the running app** — the browser tests of the form, the protocol trash and the smoke suite (28 tests) against the
dev stack, then the log read back: logins, protocols created and changed (e.g. `paratiriseis: [null, "… απόδειξη
παραλαβής σε sender@example.test"]` by `writer`), attachments, downloads, settings, trash and restore, each with the
user and the IP.
