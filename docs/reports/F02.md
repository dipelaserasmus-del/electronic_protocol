"Characterization" tests record **what the app does today**, including its bugs. When a later task fixes
a bug, the matching `known_bug_*` / `known_vulnerability_*` test is replaced by one asserting the correct
behaviour — that flip is the evidence the fix works.

## Behaviour now locked by tests

- Login by username; wrong password rejected; guests redirected; first registered user becomes admin and closes registration.
- New-protocol form proposes max(number of year)+1; dates stored as integer `Ymd`; `dd/mm/yyyy` enforced.
- Subject > 255 characters rejected (current limit, D01 will change it); incoming fields required together.
- Special characters (`--`, quotes, `&`, `%`, `<b>`, `\`) are stored verbatim through the normal form.
- Attachments stored under `arxeio/<folder>/<num>-<date>_<name>`, expiry date from retention years.
- Edit, copy-as-new, receipt page; readers can't create or delete.
- Search: subject (partial), incoming number (partial, middle of text, MySQL), number ranges.
- Access limit setting: hides unassigned protocols on open, search and "go to number".
- Admin-only pages: users, settings, backups. All main pages render for all four roles.

## Other findings while reading the code (not yet tested)

- **B03:** uploaded attachments are named with the *typed* number, not the number actually assigned —
  with safe numbering ON, files can carry a different protocol number than their protocol.
- **B03:** the date is kept by the server when typed; the reported date reset is therefore probably in the
  form's JavaScript or the redirect after an error — to be traced in B03.
- **B01:** `--` saves fine through the normal form, so the reported error must come from another path
  (email registration, search or a JavaScript check) — to be reproduced in B01.
- Editing a protocol overwrites `user_id` (the original author) with the editor.
- Search with a non-numeric "from number" or an assignee name that matches no user → 500 (B07).
- Next number without "active year" uses the most recently *created* row, not the highest number.
- Deleting a protocol hard-deletes its files (no trash) — covered by R4b.
