| | |
|---|---|

## What was wrong
CI's *Dependency security audit* (`composer audit`) failed on every pull request from 2026-11-26. Advisories
published on 2026-11-25 affect Symfony packages the application uses, all fixed in 8.1.12:
- `symfony/mailer`: CVE-2026-133755, the mailer trusts replies a man in the middle injects right after STARTTLS (the
  application sends receipts and notifications over SMTP);
- `symfony/routing`: CVE-2026-133746 and CVE-2026-133754, the URL generator can produce links to another host;
- `symfony/http-kernel`: CVE-2026-133743, inline fragments let untrusted forwarded headers change the request.

## What changed
`composer update "symfony/*" --with-dependencies`, patch versions only (`composer.lock`; `composer.json` is
unchanged):
- 8.1.12 for:
  - `symfony/mailer`, `symfony/mime`, `symfony/routing`;
  - `symfony/http-kernel`, `symfony/http-foundation`;
  - `symfony/console`, `symfony/finder`, `symfony/process`, `symfony/string`, `symfony/translation`,
    `symfony/var-dumper`.
- `symfony/polyfill-php85` 1.44.0 and `egulias/email-validator` 4.0.5.

## How verified
- `composer audit`: «No security vulnerability advisories found».
- Full PHPUnit suite: 698 tests, green. CI (with the browser tests) on the pull request.
