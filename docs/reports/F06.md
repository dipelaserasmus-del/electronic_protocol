# F06 — 502 Bad Gateway after Docker restarts the app container

| | |
|---|---|
| Status | ✅ Fixed (Docker stacks only: demo, real-data copy, `docker-compose.yml`) |
| Branch | `task/F06-nginx-reconnect` |
| Found by | the owner, on the Mac, during L02 set-up (2026-11-15) |

## What was wrong
Docker Desktop's engine stopped answering and was restarted. Afterwards "Demo: start" finished with no errors, but
http://localhost:8080 answered **502 Bad Gateway**. The logs showed the cause:

- the `app` container (PHP) had been **recreated** and got a new internal address (`172.19.0.2` → `172.19.0.6`);
- `nginx` kept running and still sent every request to the **old** address
  (`connect() failed (111: Connection refused) … upstream: "fastcgi://172.19.0.2:9000"`).

`docker/nginx/conf.d/app.conf` had `fastcgi_pass app:9000;`. With a fixed host name, nginx looks up `app`
**once, at start-up**, and never again, so the only cure was restarting nginx (`docker restart ep-dev-nginx`).

## Fix
`docker/nginx/conf.d/app.conf`:
```nginx
resolver 127.0.0.11 valid=5s ipv6=off;   # Docker's internal DNS
set $php_upstream app:9000;
...
fastcgi_pass $php_upstream;               # a variable makes nginx look the name up while running
```
nginx now asks Docker's DNS for `app`'s address again at most every 5 seconds, so a recreated app container is found
automatically. Side benefit: nginx also starts if `app` is briefly missing, instead of exiting.

The production server is not affected: it doesn't use this Docker nginx configuration.

## How verified
New test `tests/shell/nginx-reconnect.test.sh` (needs the running demo stack, uses no data): it recreates **only**
the app container while nginx keeps running. Placeholder containers make sure the app really gets a new address,
because Docker otherwise often hands the old one back. Then it checks that http://localhost:8080/login answers 200.

| Run (on the owner's Mac, Docker Desktop, arm64) | Result |
|---|---|
| old config | `app container moved: 172.19.0.8 -> 172.19.0.7` → **FAIL** (still 502) |
| new config, 4 runs | app moved each time → **PASS** (200), placeholder containers removed |
| `nginx -t` | configuration OK |
| browser tests `./dev.sh e2e` on the Mac | 7 passed, 1 failed: `email-registration.spec.js` (timeout: the click never sends the registration request). It fails **the same way with the old config**, so it is a separate, Mac-only problem of that test, not caused by F06 (it passes on Linux/CI) |
| CI | new step in the "Browser tests (full Docker stack)" job, after the browser tests |

## Owner actions
None. After you get this version, nginx is restarted the next time you run "Demo: start" or "Real data: start" (or
right away with `docker restart ep-dev-nginx`), and from then on this doesn't happen again.
