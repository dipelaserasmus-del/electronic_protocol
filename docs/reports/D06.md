# D06: folder description → TEXT

| | |
|---|---|
| Status | ✅ Done (the column change runs at the final deployment, with `migrate`) |

## What was asked (owner, 2026-11-18)
The owner will send the full list of folders (Φάκελοι) with titles and full descriptions. A folder's description
holds only 255 characters; make it TEXT. "Very important": on the task list.

## What was there
- `keepvalues.describe` and `keepvalues.remarks`: VARCHAR(255). A longer description is refused by MySQL.
- The folders page (*Φάκελοι*, `/keep`) had two text bugs:
  - the edit box showed a stored line break as the text `<br />`, so each save added `<br />` to the description;
  - the list printed the description and remarks without escaping (a `<` in the text became HTML).

## What changed
- Migration `2026_11_18_000001_folder_description_text`: `describe` and `remarks` → TEXT (at least 16,383
  characters). TEXT cannot keep the plain index on `describe`. Nothing searches by it, so the index is dropped. The
  migration is safe to run twice.
- The folders page accepts up to 16,000 characters in each (`Keepvalue::TEXT_MAX`, room for 4-byte characters) and says
  so when the text is longer.
- The edit box shows the text as stored; the list shows the line breaks and escapes the text.

## How verified
- PHPUnit `FolderDescriptionTest` (5):
  - both columns are TEXT and the index is gone;
  - the migration runs twice;
  - a 3,000-character description with a line break and 600-character remarks are saved exactly;
  - the edit box has no `<br />` and the list escapes `<`;
  - 16,001 characters are refused.
- Full suite: PHPUnit 351.

No browser test: the folders page is still the old screen (rebuilt in R6b).
