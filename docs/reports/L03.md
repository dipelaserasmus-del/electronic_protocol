|---|---|

## What was asked (owner, 2026-11-23)
In the local real-data copy (http://localhost:8081), try the inbox with real e-mails from a temporary mailbox made only for
this. Its login comes from a `.env` file, and it is chosen in *Ρυθμίσεις → Λογαριασμός εισερχομένων*.

## What was there
The real copy always used the local mock mailbox (GreenMail), on purpose. *Λογαριασμός εισερχομένων* offered only
`default` (the mock), `gmail` and `sch`. The last two have empty logins in `config/imap.php`, so neither could be used
without editing code.

## What changed
- **`config/imap.php`:** a new account `test`, read from `TEST_IMAP_HOST`, `_PORT`, `_ENCRYPTION`, `_VALIDATE_CERT`,
  `_USERNAME` and `_PASSWORD`. It exists **only when `TEST_IMAP_HOST` is set**, so other installations never see it.
  The default (mock) account is unchanged.
- **Ρυθμίσεις:** an account may have a `label`. The select shows the test account as *Δοκιμαστικός λογαριασμός
  (its username)*. The other accounts keep showing their names.
- **Where the login lives:** `local-data/test-mailbox.env`, inside the owner's git-ignored private folder, never in
  the repository.
  - `./dev.sh real up` creates it, empty, from `docker/dev/test-mailbox.env.example`.
  - `docker-compose.real.yml` passes it to the app container (`env_file`, optional).
  - `real up` prints *Test mailbox: set* once it is filled in.
- **Safety kept:**
  - The account is used only after an administrator chooses it in Ρυθμίσεις.
  - `./dev.sh real load` still switches back to `default`.
  - Outgoing mail still goes to Mailpit.
  - The demo stack (8080) and CI never read the file.
- **Guide:** [docs/LOCAL-REAL-DATA.md](../LOCAL-REAL-DATA.md#a-temporary-test-mailbox-optional) has the steps.

## How verified
- **PHPUnit `TestMailboxAccountTest` checks:**
  - no `test` account without a host (also with an empty one);
  - the account's values and defaults (993 / ssl / certificate checked), and the label;
  - Ρυθμίσεις show the label and save `test`;
  - an unknown account is refused.
- **Shell tests (`tests/shell/dev-sh.test.sh`) check that `real up`:**
  - creates an empty file;
  - keeps a filled-in one;
  - says *Test mailbox: set*.
- **Docker Compose:** with invented values, `docker compose config` shows `TEST_IMAP_*` in the app container only
  when the file exists, and the real-copy configuration is valid without it.
- **In the running dev app:**
  - the test account, pointed at the mock mailbox, appears in the list as *Δοκιμαστικός λογαριασμός
    (protocol@school.test)*;
  - it opens through the real IMAP client (counts only).
- **No browser screenshots:** the option exists only with the owner's private login, and the real copy holds real
  data. Check 54 in [OWNER-TODO.md](../../OWNER-TODO.md) is the owner's browser check.
- **Full suites:** see the PR.

## Owner actions
1. `./dev.sh real up`, fill in `local-data/test-mailbox.env`, then `./dev.sh real up` again.
2. On 8081, *Ρυθμίσεις → E-mail → Λογαριασμός εισερχομένων* → *Δοκιμαστικός λογαριασμός (…)* → *Αποθήκευση*.

Use only the temporary mailbox. Registering an e-mail moves it out of that inbox.
