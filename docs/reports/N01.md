`composer audit`: no advisories, no abandoned packages.

**Not updated on purpose:** the watermark package's next `dev-main` commit replaces the prebuilt `markpdf` executables that
the app runs on PDFs when stamping, and changes the stamp (first page only, new position). That is a behaviour change
from an unreviewed binary, not a routine update, so it is pinned. Stamping is off by default (`putStamp = 0`); revisit
it with R4a (secure file handling).

## Production server
Today: Windows 11, XAMPP (Apache), PHP 8.1.25, MariaDB 10.4.32, with php-imap (owner, 2026-11-16). PHP 8.1 is out of
security support and can't run this code (needs 8.4.1+).
**Owner decision (2026-11-16): after the rebuild, production runs the Docker stack**, the same image and MySQL 8.4 that
dev and CI test, so no XAMPP/MariaDB compatibility work is needed. The owner migrates the old database and files into it.
That path is the one `./dev.sh real load` already uses (MariaDB dump → MySQL 8.4, `migrate:adopt-legacy`, F04/F07),
already proven on the owner's Fedora copy (L01). The final deployment guide builds on it.
(The full suite was also run once against MariaDB 10.4.34 locally: 130/130 green. Not kept in CI after the Docker decision.)

## How verified
- **New characterization test first** `tests/Feature/Legacy/StoreFromEmailTest.php` (3 tests), written and green on
  parser v3 **before** the upgrade, then green on v4: an invented e-mail with an ISO-8859-7 Q-encoded subject, a UTF-8
  B-encoded sender name, an ISO-8859-7 quoted-printable text part, an HTML part and a PDF with an RFC 2231 Greek file name.
  Checks the stored subject, sender `Name <address>`, date/time, summary, the `.eml` copy, the HTML-page variant
  (`saveEmailAs` empty) and the attachment's name, type and bytes; a missing saved e-mail creates nothing.
- Full suite: 130 tests green on PHP 8.5 (dev) and in CI on PHP 8.4 + 8.5 / MySQL 8.4.
- No user-visible change, so no new browser test; the existing e2e suite runs in CI.
