# S00 — Close the open administrator registration

| | |
|---|---|
| Status | ✅ Fixed |
| Severity | Critical (anyone who can reach the app could become administrator) |
| Branch | `task/S00-registration` |

## The vulnerability (confirmed before the fix)
- `POST /register` was always routed; only the *form* was hidden after the first administrator registered.
- `RegisterController::create()` never checked whether registration was closed.
- New users had no explicit role, and the database default `role_id = 1` is **Διαχειριστής**.

Test `known_vulnerability_anonymous_post_register_creates_admin_when_closed` (F02) proved that an
anonymous request created an administrator account on a closed installation.

## The fix
| Change | File |
|---|---|
| One rule for "registration open": marker file absent **and** no active administrator in the DB | `app/Support/Registration.php` |
| `POST /register` refused with 403 when closed; form redirects to login | `app/Http/Controllers/Auth/RegisterController.php` |
| First user gets the admin role **explicitly**; registration closes immediately | same |
| Registration rate-limited (5 per minute per IP) | `routes/web.php` |
| Login / forgot-password / welcome pages use the same rule for the "Register" link | `Auth/LoginController.php`, `Auth/ForgotPasswordController.php`, `routes/web.php` |
| DB default `users.role_id` changed from 1 (admin) to Αναγνώστης (least privilege). Existing users unchanged | migration `2026_11_12_000001_users_role_default_reader.php` |

The fresh-installation flow is unchanged: on a new, empty system the first person who registers becomes
administrator, then registration closes. Recovery still works: if every administrator is deleted
(and the marker file removed), registration reopens.

## Evidence

**Automated** — `./dev.sh test`: 55 tests, 166 assertions, all pass. New/changed tests in `tests/Feature/Legacy/AuthTest.php`:

| Test | Asserts |
|---|---|
| `anonymous_post_register_is_refused_when_registration_is_closed` | 403, no account created (replaces the vulnerability test) |
| `post_register_is_refused_while_an_admin_exists_even_without_marker_file` | deleting the marker file doesn't reopen it |
| `register_form_redirects_to_login_while_an_admin_exists` | form not reachable |
| `inactive_admins_do_not_block_first_registration` | recovery path still works |
| `registration_is_rate_limited` | 6th attempt per minute → 429 |
| `default_role_is_reader` | a user row without role is a reader, not an admin |
| `first_registered_user_becomes_administrator_and_closes_registration` | fresh-install flow unchanged |

**Manual, against the running dev stack** (with an admin present):
```
GET  /register -> 302 → /login
POST /register -> 403
users table: no "intruder" account
```

## Owner action — after deploying
1. Check the `users` table for administrator accounts you don't recognise (the hole existed before this fix).
2. Run the database migration: `php artisan migrate` (in Docker: `docker compose exec app php artisan migrate`).
